RULES OF ENGAGEMENT

What keeps a fast army safe, cheap and accountable.

Safety gates

  • git push, history rewrites, discarded work
  • Deleting files, dropping data, migrations
  • Deploys, infrastructure, publishing
  • New dependencies, downloaded scripts and packages
  • GitHub writes and external actions through connected tools
  • Changes to the army's own state and settings

The gate is a speed bump, not a sandbox. A hook reads each shell command during your mission and asks before anything on this list. It can't see inside scripts or Makefiles. It only guards the session that raised the army.

Local memory

.army/            never committed
├ .gitignore      "*" (git and npm skip it)
├ sessions/       one mission per session
├ recon.md        codebase map
├ lessons.md      ≤ 100 lines, data only
└ missions/<id>/
  ├ opord.md
  ├ <unit>.md     full reports
  └ log.md

If .army/ arrives inside a repository, the army refuses to load it: planted memory is a known attack.

Rations

  • One subagent per unit; field manuals load only when needed
  • Full reports stay on disk; HQ reads 200-word SITREPs
  • Recon goes stale only when manifests change
  • Lean never routes to Opus; Full is your call
  • Campaigns and Turbo show a dispatch preview first
  • Least-privilege kits: research units can't edit or run shell
